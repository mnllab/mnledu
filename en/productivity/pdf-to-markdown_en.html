You need to turn a confidential contract or internal report into Markdown, but uploading it to an online converter feels like a data-leak risk, and retyping it by hand keeps mangling the tables and captions. This converter was built for exactly that gap. Your file never leaves the browser, and awkward mid-sentence line breaks and headers that repeat on every page get cleaned up automatically.

Why there's no server upload

PDF.js is a library that parses PDFs inside the browser, so once a file is read into memory with FileReader and its text coordinates are pulled out, the conversion is done — there's simply no point where a server needs to get involved. For a tool that handles documents that should never leave the building, like contracts or HR files, not building a transmission path in the first place is the surest form of security.

How tables are detected — a coordinate-spacing heuristic

Every piece of text inside a PDF carries its own x/y coordinates. When the gap to the next piece on the same y-value (line) is more than 3.2x the average character width, that gap is treated as a column boundary. Calling any single wide gap a table would produce too many false positives, though, so a run is only promoted to a table — and rebuilt as Markdown table syntax — once two or more consecutive lines repeat the same column count within a tolerance of ±1. A single column, or a completely different column layout on the next line, is treated as an ordinary paragraph instead.

How broken line breaks are picked out

PDFs force a line break to fit the page width, so any line that doesn't end in a sentence-ending mark like a period, question mark, or closing bracket gets joined with the next line. The exception is when the next line starts a new list item (- , 1. ) or is a caption or table row — those are left alone. Otherwise a list would collapse into one line, or the sentences around a table would bleed into the table itself.

How repeated headers and footers get removed

A short line (80 characters or fewer) that appears word-for-word on 60% or more of all pages is treated as a recurring header — a company name, document title, "Confidential" stamp, and so on — and removed automatically. Page-number patterns (3, Page 3 of 10, etc.) are filtered out separately. Documents shorter than 3 pages skip this logic entirely, since there isn't enough of a sample to judge repetition — otherwise a 2-page document could have a coincidentally-shared sentence mistaken for a header and deleted.

Why on-device AI sticks to a 30–80MB model

Loading a generative LLM over 1GB into the browser will freeze or crash the tab on a lower-end laptop. So this tool uses a lightweight model tuned for text correction and formatting that comes in around 80MB when quantized: Xenova/flan-t5-small. Even that would freeze the screen if it ran on the main thread, so model loading and text generation both happen inside a Web Worker, split into paragraph-sized pieces sent one at a time while a progress bar tracks the work. Tables and caption placeholders are excluded from the AI pass entirely, so the model can't damage the Markdown syntax itself.

How figure and table captions are preserved

When a line starting with a figure number — "Figure 1.", "Table 2.", "Fig. 3:" — is detected, the actual image isn't extracted; instead it's replaced with a placeholder like [🖼️ Image omitted: Figure 1. System architecture]. That way, the fact that an image existed — and what it was about — still comes through just from reading the Markdown.

Frequently asked questions

Does my uploaded PDF get sent to an external server?
No. Everything from upload to conversion happens entirely inside your browser. No network request is made even at the moment you select a file, and refreshing the page clears any data that was held in memory.
What changes when I turn on on-device AI Deep Cleaning?
A lightweight local AI model reviews the text that PDF.js already extracted and smooths out awkward line breaks and table formatting. The default mode works fine on its own — AI mode is an optional extra pass for when you want the result polished a bit further.
Does the AI model get downloaded again every time?
No. It's downloaded once on first use and stored in your browser cache, so it loads instantly from then on without downloading again. If you clear your browser storage, it will need to be downloaded once more.
Are tables in the PDF converted accurately?
Tables are detected with a coordinate-based heuristic that analyzes the spacing between columns and rebuilds them as Markdown tables. Tables with heavy cell merging or ones drawn as background images may not be recognized perfectly, so it's worth reviewing the result in the editor afterward.
Does this support scanned (image-only) PDFs?
Scanned PDFs made only of images are outside this tool's scope. It works by reading the text layer that already exists inside a PDF, so a scan with no selectable text will produce an empty result.
What if a table comes out misaligned in the result?
Turn off the 'Auto-detect tables' option on the left to receive tables as plain text and clean them up by hand instead. If that still doesn't fix it, you can edit the Markdown directly in the editor on the right.

This tool never sends your PDF to a server.
