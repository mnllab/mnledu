We've all been there: copy a table from Excel, paste it into a Word or Hangul document, and the formatting falls apart — or the reverse, retyping a table cell by cell to get it back into Excel. Sometimes matching the table's format takes longer than writing the report itself. Universal Table Data Hub auto-detects tables from text you paste in or an Excel file you drop in, lets you apply the formatting you want, and exports it straight to Word, HWPX, XLSX, or whatever format you need.

Why support both pasting and file upload

When you need to move a table quickly mid-meeting, copying a cell range and pasting it as text is far faster than opening Excel. But if you already have a tidy Excel file, uploading it as-is is easier. Both input paths convert into the same 2D array structure, so formatting and export work identically no matter which way you bring the data in.

How the delimiter gets detected automatically

If the pasted text has both a | Name | Age | pattern and a |---|---| separator line, it's treated as a Markdown table. If it contains tab characters, it's treated as TSV copied from Excel; if only commas, as CSV. The priority is Markdown > TSV > CSV because commas often show up inside Markdown table syntax too — checking for commas first would break those tables. Text with no delimiter at all is treated as a single-column table, one row per line, so no data gets dropped.

Why 'inline with text' and table width are separate options

In Hangul (HWP), a table placed as a floating object tends to drift out of position and overlap content as paragraphs grow. That's why 'Inline with text' defaults to on, keeping the table anchored to the surrounding text flow — and why table width is set directly in millimeters, making it easy to match the usable width on an A4 page after margins (around 160mm).

How the export formats were chosen

DOCX is for dropping straight into Word or sharing via Google Docs, HWPX is for Hangul documents, XLSX is for further spreadsheet work, and MD/CSV are for developer docs or data migration. 'Copy formatted table' skips the file entirely for a quick Ctrl+V — it copies an HTML table with inline CSS to the clipboard so cell borders and alignment survive the paste.

Is the table data I paste in sent to a server?
No. All parsing and file generation happens entirely in your browser — no data is ever sent to an external server.
If I upload an Excel file, is the original file stored on a server?
No. The SheetJS library reads the file only in your browser's memory, and the data disappears when you close the tab.
Do I have to choose the table delimiter myself?
No. Tabs (TSV), commas (CSV), and Markdown table syntax are all detected automatically. If detection is ambiguous, you can still set the delimiter manually at the top.
Will a file exported as HWPX actually open in real Hangul (Hancom Office)?
Yes — it's generated following the HWPX OWPML standard and designed to open in Hancom Office 2020 or later. Very complex formatting (nested tables, special objects, etc.) isn't supported, though.
What does the 'Inline with text' option do?
In Hangul (HWP), it decides whether a table flows inline with the surrounding text or floats as a freely-positioned object. Turning it on is recommended so the table doesn't drift while you keep editing the document.
How many rows and columns can it handle?
We've confirmed real-time processing up to several thousand rows within typical browser memory limits. For very large datasets, only part of the data is shown in the live preview.

This tool runs 100% in your browser and never sends data to a server. Table data you enter and Excel files you upload aren't stored anywhere, and disappear as soon as you close the tab. You can use it on sensitive internal data without worrying about it leaking externally.
